# Data

What the airline publishes for the app — the aeronautical base, the procedures, the aircraft, the weather — and the state of each data set. This screen is for reading, and offers actions on every group: Download the sources, Build, Purge, then Publish.

## How to use it

<a id="data-cycle"></a>**The cycle in force.** At the top, the current AIRAC cycle (for example 2610), its dates and the number of days before the next one. Below, "Launcher of this workstation" or "No launcher: read only" says whether this computer has a launcher.

<a id="data-coverage"></a>**The coverage.** The list of zones (countries, regions) this workstation follows. On the first opening it holds every zone the airline publishes; the list is kept on this device. “Add a country” puts into the coverage a zone the suite knows, even one nobody publishes yet: it is ticked for “Build”.

<a id="data-packs"></a>**Country packs.** Beside the map, with the list of zones (under it on a phone), when AeroDB gives packs: one row per regional pack (Western Europe, Asia…) with its number of countries and its size. The row is a **“the whole pack in the coverage” switch**: on, all its zones are in the coverage (ticked); half, some are; turning it on adds the missing ones; **turning it off removes all its zones from the coverage**, after a question that names them: they are unticked and leave this workstation's list, **nothing is purged** (their files stay). Hovering a row with the mouse, or pressing it on a phone, **lights its zones on the map**. Under the switch, a folded **“Countries (n)”** lists the pack's countries with a tick each (ticked = in the coverage): ticking a country adds it alone, nothing is downloaded or built; open, it scrolls inside itself. An empty pack says why (“no zone and no source today”). Regions and **themes** (islands, deserts…) share one block with two tabs, “Regions” and “Themes”. A theme is a fold that shows its countries **in the same grid as the list of zones**: one tick per country (ticked = in the coverage), the name; ticking a country adds it to the coverage, unticking it removes it after a question (nothing is purged); at the head of the grid, a “The whole theme” switch. One button only, **“Update (n)”**, on the row of a pack of which n countries are in the coverage: the update path (download, state, then one question) on those countries only, without touching what is ticked in the list; the countries of an open fold are indented under their pack.

<a id="data-states"></a>**The States.** Under the coverage, the States are sorted by colour: green, procedures are already published; orange, they can be read on demand; red, nothing is readable. The reason is written on each line, the colour is never alone. Beyond seven lines, "n more" unfolds the rest.

<a id="data-group-base"></a>**Aeronautical base.** One line per source that feeds a zone of the coverage: its cycle, its age ("published 3 days ago"), the number of zones published and a state badge. Tap a line to see the source's link with its address, its licence, the zones it feeds and what each zone has published.

<a id="data-group-proc"></a>**Procedures.** The procedures of France (SIA eAIP) and of the United States (FAA CIFP), with the number of aerodromes published. Each State line also says the aerodromes whose procedures are already here (“France — 3,069 aerodromes, cycle 2611”; “n aerodromes read” for the other States).

<a id="data-group-aircraft"></a>**Aircraft.** The aircraft types and their performance: the edition date, the number of types and of files. After 28 days the badge turns orange.

<a id="data-group-weather"></a>**Weather.** The world weather and the NAT tracks are published with the website: these lines have neither a cycle nor a badge.

<a id="data-world"></a>**World synoptic (GFS).** In the Weather group, one row for the world synoptic forecast of the Atmosphere map: its state (“Not on this workstation” until one is published, “Over 12 h old” as it ages), the GFS run, the number of steps, its weight and its age. “Build” makes it on the workstation (about 2 minutes the first time; a few seconds if the run is already there, it is then reused). It is published **locally**, in data/weather/world/: never synchronised nor committed. A failure says its reason (no run published or NOAA unreachable, invalid folder, time exceeded) and the old publication stays.

<a id="data-zone-link"></a>**Links to a zone.** `#data?zone=<id>` opens the base, ticks that zone alone and brings “Update” on screen; a zone that is not in the defined countries is said, with “Add a country”. The reasons of a zone to rebuild also count: file of the cycle absent, built before a source's file was there, file present but the “personal” box not ticked (rebuild with the box), file to drop. A **notice** (“zone without points or airways: the source does not carry them”) does not make the zone stale.

<a id="data-states-pill"></a>**The badges.** "Up to date": nothing to do. "Cycle out of date": the published cycle is older than the cycle in force (orange, red after a week). "Old parser": published by an older version of the builders. "Over 28 days old": a set without a cycle, published more than 28 days ago. "Not in the repository": nothing is published. A group opens by itself when one of its lines needs attention.

<a id="data-more"></a>**The other data sets.** At most seven lines per group; "n more data sets" unfolds the rest and the sources that are only considered or set aside (their link, licence and status).

<a id="data-build"></a>**Build the base.** At the top of the Aeronautical base group, the "Update the base" panel acts on the ticked zones with three buttons, in this order: Download · Build · Purge. "Build" rebuilds the base of the ticked zones on this workstation's launcher: a windowless browser (Edge, else Chrome) builds the zones one after the other, and each one is saved to the data repository as soon as it is ready. Every zone of the coverage is ticked at the start; untick the ones you do not want to redo. The three buttons go grey together, with their reason written once below: "The workstation launcher is needed", "Another operation is running", "Tick at least one zone", "Offline". When the launcher refuses because another operation is running, a **card** says which one (its name, its UTC start time, where it is, alive or "not answering") with "View" (back to its follow-up), "Stop" and, only when it no longer answers, "Release" (the launcher checks before lifting the lock); a file sent and refused for the same reason shows the same card.

<a id="data-build-personal"></a>**Personal-licence sources.** ENAIRE (Spain), NATS (United Kingdom), AirNav (Ireland) and the X-Plane data are listed when a ticked zone uses them. **One box** unlocks them all: “I certify that I use the data for my personal use” (never ticked by default: tick it only if the data repository is used by you alone). Ticked, it is remembered on this workstation, found ticked at each opening of Data, and goes out with every “Download”, “Build” and “Update” (every personal-use source of the ticked zones); only its own box undoes it. With a launcher on this workstation, **the launcher holds the tick** (data/local/personal_use.json): at the opening the box shows ITS file, each click rewrites it, and the tick of this page, if it was already set, is handed to it once; if the launcher refuses, the box goes back as it was and says so. This protects against forgetting and against page code that would declare the tick for you; a script of the same origin could, however, call the same route. What is proprietary (X-Plane, EUROCONTROL) stays **read on this workstation only**: never in the published base nor in an export, ticked or not. The “Sources and licences” link opens the page that lists each source (publisher, licence, credit, date). An old per-source box that was ticked becomes the one box. **A zone built with one of them is published in your data repository**; only X-Plane and EUROCONTROL stay read on this workstation, never published.

<a id="data-build-run"></a>**While it builds.** A bar, "n of m zones", the step and the elapsed time; one line per zone says waiting, building (n / m sources), built, failed with its reason, or cancelled. "Stop" asks for the stop: the zone in progress finishes, the zones already built are kept. You can leave the screen: the build goes on in the launcher and is found again when you come back. If the launcher stopped on the way, the screen says "Build interrupted" with the last state of each zone: start again, unticking the zones already done if you like.

<a id="data-build-end"></a>**At the end.** A notification gives the counts ("Base built: 3 zones; 1 failed (gb)") and the summary stays in the panel with what to do: a failed zone (the reason is written on its line: windowless browser, time limit, invalid output, could not write…), a stopped build, no browser found ("Neither Edge nor Chrome was found on this workstation: install one of them."). The state of the lines is read again afterwards. When a source of the base is of a past cycle (the SIA at 2610 while 2611 is in force), one orange line names it once, with its page and the file to take: "Build" would rebuild the old cycle. A zone without a dated source (openAIP, GeoNames, relief) is never said to be out of date. When the cycle in force of a source to take by hand is missing, an orange line under the buttons says so ("SIA France 2611 missing: download export_xml_bd_SIA_<date>-v<nn>.zip from the SIA site"); "Take the downloaded file" then becomes the main button and "Build" loses it. When a take leads nowhere, the reason is written **on the zone's line** (what was found in Downloads, what is missing, what is refused) and stays there until the next attempt; "Choose the file…" is offered on that line as soon as it carries a message or waits for a file; a greyed button says why. A hand-taken source (NAV Portugal: a zip carrying the ISO, the ISO alone, a folder) offers "Choose the file…" from the start, with its steps; when a file is seen in Downloads, "Take the downloaded file" is the main gesture and "Choose another file…" a link under it; the line says the edition read ("edition of 1 October 2026"), whether the file is the previous cycle's or a future edition, and each refused file with its reason. The list of sources the upload takes comes from the launcher alone. That line comes from the last download or build (the journal keeps it): nothing is started to read it, and "Cycle X out of date" names the source at fault.

<a id="data-update"></a>**Update.** The main button of the base panel: it downloads the sources of the ticked zones (like “Download”), then reads the **state of each zone** from the launcher and rebuilds only those that are not up to date and that the build can handle. A single question names those zones, the reason for each (one sentence when there are many: “45 zones: built with an older parser”) and their size, and says it may take a while; if nothing needs rebuilding, a sentence says so. The zones that wait for a file from Downloads are named: “Take the downloaded file” first. If the state cannot be read, nothing is rebuilt. “Update” is the only button in view; **“Detail”** (folded) holds “Download”, “Take the downloaded file” (which stays in view, as the main button, when a manual cycle is missing), “Rebuild all” (the former build, on the whole selection whatever its state: after a purge, or when in doubt) and “Purge”. Beyond 60 ticked zones the verbs work in runs of 60, one after the other; “Purge” first plans each run, then asks **one single question** that gives the sum. Each zone of the list and of the map says its state, as the launcher gives it: **green** (up to date), **orange** (to rebuild: touch the pill to read why — newer source, source files changed, older parser, missing files, a file to take…), **grey** (never built), **red** (the last build failed), **blue** (the page is building it). Zones are **independent**: a download or a run of 60 zones that fails does not stop the others, the failed zone is a line with its reason. At the top of the base panel, a **state sentence** (“Cycle 2611, in force since … Your base: 58 zones up to date · 2 to rebuild · 2 failed · 1 waits for a file · 3 without state”): a zone without state is counted; each number is a button that unfolds, right below, the zones it counts (with their box, ticking nothing, no scrolling). Under it, **the** button “Update (n)” (the whole coverage) or “Update the selection (n)” (at least one zone ticked and at least one unticked), and the line of what it will do (“download 3 zones, rebuild 2 zones”); the progress and the final summary come right below. All up to date: “Everything is up to date.”, no button. “Everything is up to date.” is said only when nothing is left to rebuild, failed, waiting for a file or for the tick; otherwise the line says what waits for your hand. A zone whose source is under a personal licence and whose tick is missing offers no file: its line says to tick “I certify…” (link to the box) and the state sentence counts them apart (“wait for the tick”). A remark from the launcher (“no points or airways: the source does not carry them”) is information, never a state. The state word of a line (“To rebuild”) opens its reason (“why?”) without moving the list; a reason the page does not know is shown by its code. The map legend has three states: up to date, to do, failed. On the line of a failed zone, **“Try again”** (the build of that zone alone); on the line of a zone waiting for a file, what it waits for and **“Take the downloaded file”**, which then starts the build of the zone. **Update only does what is not up to date**: the state of every zone is read **before** anything is downloaded; a zone that is up to date is skipped, a zone whose sources of the cycle are already there is **not downloaded again** (its build only), and a line says what is going to be done (“1 zone to download, 3 zones to rebuild, 2 zones already up to date”). When a source refuses the download (HTTP 403 for instance), the zone says which one and what it answered (“FAA: download refused (403)”) with **“Try again”** on its line, which replays the download of that zone alone; the other zones go on. “Rebuild all” stays the gesture that redoes everything. **Beyond 60 zones** the state is read in runs of 60 and merged: a coverage of 78 zones was read for the first 60 only, the others had no pill and no proposal to rebuild. When the **FAA** refuses the automatic download (United States, HTTP 403), the zone’s line also offers **“Choose the file…”** and the direct link to the NASR subscription page, where to take the three sets of the cycle (FIX, AWY, NAV). When the FAA refuses, drop the **three NASR sets** by hand (FIX, AWY, NAV, with the FAA's original file names): each recognised upload is counted, the screen says what is missing, and at the third the zone's download reads them and the build starts. The **Country packs** block is folded when the screen opens. A tap on “n to rebuild” (or “failed”) **ticks those zones**, shows them alone, brings the list into view and says in one line what to do.

<a id="data-select"></a>**The map, the country groups and a country's sheet.** Under the state sentence comes **the map** (the country outlines, framed on your defined countries; three states: up to date, to do, failed; a hatch where procedures exist; “See the whole world”), then **the country groups** (one line per group: “12 of 14 up to date · 2 to do”; only one group opens at a time, its countries get a blue border on the map, the hovered country fills in alone; the group's “Update”). Touching a country, on the map or in a group, opens **its sheet** (right of the map on a wide screen, full screen with “← Back” on a phone): its state, the date of its build and, for each source, the three ticks put by the tool alone (downloaded · built · published, with the date and the edition); for a hand-taken source, the inventory of its files in three beats (what it is, where to find it, the expected name) with those seen in Downloads and those missing. A source unavailable at its publisher is set apart. There is no flat list of zones and no selection any more: the button at the top acts on the whole coverage, a group's on its countries. On the sheet one acts: “Update this country” (it says what it will do, and why it is greyed); for a hand-taken source, “Take the downloaded file” is the main gesture when a file is seen in Downloads, “Choose another file…” a link under it, and “Choose the file…” alone when nothing is seen (the SIA zip for DIRCAM: the page reads only the useful member, without loading the zip). Between the map and the groups, **“what is left to do this month”** (“AIRAC cycle 2611: 12 done out of 15”): one line per source not done, with its three ticks put by the tool (downloaded · built · published, the date or the reason in words), leading to the country's sheet; the sources already done are folded, those unavailable at their publisher are set apart and do not count. The **wheel** zooms the map wherever the pointer is, over a country's outline included (at the end of the zoom it scrolls the page again); **hovering a group** of the grid outlines its perimeter in blue on the map without framing it (the framing stays with the click); a country picked with Shift + click stays outlined in the same blue as long as it is picked. The **defined countries** (“the coverage” in the specs and in the code) are the countries whose base this workstation builds: one is added from its sheet (“Add this country”) or several from the banner of the map (“Add these countries (n)”), one is removed from its sheet (“Remove this country”).

<a id="data-download"></a>**Download.** The "Download" button fetches, on this workstation's launcher, the raw sources of the ticked zones (openAIP, FAA, UK Mil AIP, NAV CANADA, today's NAT tracks; ENAIRE only if it is ticked among the personal-licence sources). One line per zone says where it stands ("downloading (2 / 3 sources)") and, below it, one line per source: downloaded (n files), unchanged, failed with its reason and HTTP code ("HTTP 404"), skipped (licence not declared) or manual. What has not changed is never rewritten. At the end a notification gives the counts ("Downloaded: 2 zones changed, 1 unchanged; 1 failure"); the sources the launcher does not download (the SIA, for example) are listed by name, with a link only if their address is https, "to be dropped in by hand"; if source files tracked by git were modified, the screen says so ("n source files changed, outside the synchronised data"). "Nothing to download for these zones": none of the ticked zones has a downloadable source. Two downloads cannot follow each other within 30 s: the screen says "Try again in n s".

<a id="data-zone-map"></a>**The map of the zones to tick.** Above the list of zones (base panel) and of States (procedures panel: France and the United States), a real map (the application's shared map base, as the Map and the Weather use) draws the zones filled with the tint of their state: you pan and zoom it with the finger, and the "Recenter" button brings the view back to all the zones. Tapping a zone ticks or unticks it, exactly like its box in the list (one selection: the map and the list are both redrawn from it); dragging or pinching the map ticks nothing. A country the suite knows but that is not in your defined countries is drawn in grey (“not defined”): tapping it adds it to the coverage and ticks it, like “Add a country”; tapping it again unticks it. A country of the coverage is only ticked or unticked: a tap never removes it. With the keyboard, the list is the path: its boxes tick with Space. The colour follows the state (up to date, cycle out of date or missing, running, not in the coverage: the legend under the map names them in words) but is never alone: a ticked zone has a thick outline and a fuller tint. During an operation, the map is frozen like the list. An outline that is only the zone's frame is dashed; the legend recalls it. When the map cannot come (offline without a map background in memory, no WebGL, or the frame does not give the outlines), the list stands alone, with no error message. When the map is zoomed in enough (the States map), the aerodromes whose procedures are already here appear as dots: green when up to date, orange when of a past cycle; a tap on a dot says its code and its cycle, without ticking the State. Farther out, only the count on the State’s line stays. It is a reading of this device’s base: nothing is downloaded or written.

<a id="data-route"></a>**Route (RAD, FRA points).** In the Procedures group, one more row: the EUROCONTROL workbooks of the route calculation. It says the cycles present on this workstation (“RAD of … · FRA points of … · imported n days ago”) and takes the pill of the other sets: “Not in the repository” with no import, “Cycle out of date” when the latest RAD precedes the cycle in force, “Up to date” otherwise. “Import from Downloads” first looks, writing nothing, for the `RAD_<cycle>_v….xlsx` and `eurocontrol-airac-<cycle>-fra-points-….xlsx` workbooks in your Downloads folder, then asks a question that names them (kind, cycle, size) and recalls the licence: EUROCONTROL Network Manager documents, use by the company, published in its private repository only. After “Import”, only the workbooks shown are compiled into `data/route/` (a cycle replaces the same cycle, the others stay) and a commit is made; the row then says the cycles present. With no workbook in Downloads it says so and asks nothing.

<a id="data-pickup"></a>**Take the downloaded file.** Some sources do not download by themselves (the SIA for France, NATS for the United Kingdom): you download them in your browser, then "Take the downloaded file" (the second button of the base panel, and under the "to be dropped in by hand" line of a download) looks in this workstation's Downloads folder for the most recent zip with the expected name (for example EG_*_DS_*_XML.zip). The plan first and one question, in titled groups, one line per file: **Will be taken (n)** (country · file · size), **Ignored (n)** (country · file: the reason, for example openAIP’s “hot” layer), **To fix (n)** (country · source: what to do, for example “rename the file without space or accent” or “drop EG_*_DS_*_XML.zip into Downloads”). Seven lines show per group, the rest scrolls. The files go into this workstation’s raw sources (data/sia/, data/sia/zones/gb/…), never committed. Nothing found: no question, the screen says what is missing. The plan also sends the “personal” box: if the NATS sets are already there but the box does not declare NATS, the screen says “n NATS set(s) already taken: nothing new to take” (not “Nothing to take”) then “n NATS sets in place: the “personal” box does not declare NATS”: tick the box, then “Update” reads them. At the end: "Taken: n files (x MB)", the failures named (zip too large, nothing useful in the zip…) and "Now start Build". "Update all" never starts this take: it stays a gesture. The button is greyed with its reason if this workstation's launcher does not know the operation yet. The take only brings the zip the plan showed (name and size): if another zip arrived during the question, that source is refused ("the file changed since the plan") and nothing is taken for it; "Run the plan again" shows it anew. A zip whose name is outside the rule (letters, digits, dot, hyphen, underscore, space, parentheses) is shown by the plan but never taken: its line says "file name to rename: letters, digits, . _ -"; if nothing else is left to take, no question is asked. The openAIP exports (GeoJSON or JSON files dropped in Downloads) are not a zip: the plan shows the files one by one ("n files (x KB), of which n converted from JSON to GeoJSON") and the take sends back exactly what the plan showed. An export the suite does not read is said, never taken: an XML ("is not read (XML format): export it as GeoJSON or JSON on openaip.net") or the "hot" layer ("is not used"). If that is all there is, no question is asked.

<a id="data-purge"></a>**Purge.** The "Purge" button removes from this workstation the raw sources of the ticked zones (the ones you download again) and their caches. It first works out the plan without erasing anything, then asks one question: "Purge 15 files (14.3 MB) from the sources of Spain, France?". If the SIA files (France) are part of it, the question recalls that they also serve the outlines of the other zones when building; files tracked by git are always kept and counted. No: nothing is removed. Yes: the purge runs and the screen says "Purged: n files, x MB", with the paths refused (left in place). Nothing to remove: "Nothing to purge", with no question.

<a id="data-publish"></a>**Publish the base.** Under "Build", the "Publish the base" panel sends what was built on this workstation to the data repository. A built zone is committed whole on the workstation and also leaves at the next synchronisation: “Publish” sends it right away. It first says where the workstation stands: "3 files changed · 2 commits to send", the date of the last pass and, if there is one, the merge waiting in data/ (publishing concludes it first). Tap "Publish": one question recalls the files and the commits, then the pass runs; an endless bar shows that it is working. Meanwhile the buttons of the "Download, build, purge" panel are grey, and "Publish" is grey during any operation of that panel: one operation at a time. If the publication fails, the screen says why in the pilot's words and at which step (“The publication failed: the server refused the upload: a repository rule, or a file too big (step push)”); nothing is lost, the files stay on the workstation. Causes: the server's refusal, the remote repository changed meanwhile, Git LFS, login refused, server unreachable, conflict, busy repository, time-out, launcher error; with an older launcher the screen says so instead of guessing.

<a id="data-publish-end"></a>**At the end of the publication.** A notification gives the counts and the result stays in the panel: what was sent (files committed, files received); the files of the base kept on the workstation because a build was under way; the conflicts (the most recent is kept, see Settings › Conflicts); the files refused because they are not in the format of a data file. A failure says so in one sentence, with what the launcher answers: nothing is lost, the files stay on the workstation. The button is grey with its reason written below: "The workstation launcher is needed", "A build is running: publish when it is finished", "Nothing to publish", "The frame cannot publish the base yet: update the app", "Offline".

<a id="data-set-panels"></a>**The same buttons for every group.** Each group has its "Download · Build · Purge" panel: the Aeronautical base, the Procedures, the VFR points of the VAC charts (in the Aeronautical base group, under "Publish") and the Aircraft. The principle is the same everywhere: one operation at a time, all panels together (it is found again when you reopen the screen); one line per item while it runs, an end sentence and a notification, a line in the journal; "Purge" first works out a plan without deleting anything, then asks one question. Procedures: tick the States that are read in bulk, France (the SIA's eAIP) and the United States (the FAA's CIFP); none is ticked for you. States read through EAD Basic are never read in bulk: one aerodrome at a time, with "Read again" in Fuel or on the Map. VFR points: the cycle in force, no box to tick; "Download" fetches the cycle's VAC charts ("n charts not published yet" is not a failure); "Build" first needs this cycle's France base, the downloaded charts and pypdf (the first-install assistant installs it), and says when nothing was committed for lack of a trigram; "Purge" empties the charts cache of all cycles. Aircraft: ICAO types separated by commas or spaces (2 to 4 letters or digits); a refused code is said and nothing is sent, an empty field means the fleet's types; the lines of the run are the three steps (types, performance, SimBrief profiles). The weather has no panel: it is published with the site. A button greyed with "This workstation's launcher does not know this operation yet": the launcher of this workstation is older than the app, update it. Nothing is committed by "Download" or "Purge". "Build" commits its results on the workstation, except for the aircraft: this workstation's AircraftDB/ folder is not versioned, sending is done by "Published sheets". While a merge is waiting in data/, no build or sheets publication writes anything: the screen says "A merge is waiting in data/: synchronise first (Settings › Synchronisation)". During an update of the suite no operation starts (base, other sets, chain, file pickup, sheets): the screen says "Suite update under way: try again after the launcher restarts"; the state and the following of a job already running go on.

<a id="data-aircraft-sheets"></a>**The airline's published sheets.** Under the Aircraft, "Publish" copies the airline's sheets to the data repository. It first works out a plan without changing anything, then asks one question (sheets to copy, sheets to remove, total size); if you accept, the copy, the commit and the sending are done in one gesture. It needs your trigram (Settings › Identity); without it the screen says so and nothing is sent. With nothing to copy or remove: "Nothing to publish".

<a id="data-update-all"></a>**Update all.** The “Update all (n)” button at the top of the screen does the month's refresh in one gesture: the base (the sources to download, the zones to rebuild) then the other sets that have something to do (procedures, VFR points, aircraft), in the published order, with a single question (the plan: the AIRAC cycle, what will be touched, the size) and a single publication at the end. Beside it, a sentence says what it will do; “Base only (n)” limits it to the base. A failure does not stop the others: the summary lists each failure with its reason and “Try again”. A chain line shows the set and the step in progress, with a single “Stop”. Each other set is a **folded line** (“Procedures · up to date”) that, once unfolded, keeps its own “Update”; a country and a group keep theirs. An operation already running is shown by its card (which one, since when, how far, “View” · “Stop” · “Release”). **Shift + click** on countries of the map (or Shift + drag a rectangle; two fingers held for half a second on a phone) selects several: a banner offers “Add these countries (n)” or “Update (n)”. The journal keeps one line for the whole chain, with each set's result.

<a id="data-registry"></a>**The French aircraft register.** Under “Seen by the workstation, not read yet”, the “French aircraft register” fold is where the DGAC registrations file (`export.csv`) is deposited: its state (“deposited …” or “not deposited”), the link of the site to download it from, then “Choose the file…”. The workstation recognises it by its columns, keeps only five of them (registration, maker, model, serial number, home aerodrome), never an owner's name or address, and does not keep the original file; it says how many registrations it read. It is used to create an aircraft (“Deposit it in Data” leads here: `#data?registry=1`).

<a id="data-coverage-table"></a>**Coverage by country.** Under the groups, a folded “Coverage by country” block (nothing is read until you open it) asks the launcher what the base holds for each country: one row per country, seven columns — the country, **Points, Airways, Airspaces, FIR, Procedures, Ground** — each a number or “no” (none). Touch a heading to sort (the same one reverses), a country to see its cycle, its **sources read with their licence** and those not read yet. If the launcher is busy with another job, “Read again” asks again when it is over.

<a id="data-steps"></a>**A file to drop in by hand, step by step.** On the line of a zone that waits for a file only you can drop in, under the “Take the downloaded file” button, the list of steps: the **direct link** of the page where the file is (and, if that link no longer answers, the site’s home page), **the exact name** of each file to download with what it brings, then the button of the line. **A set with mixed cycles** (the VFR points, for example, partly of the current cycle and partly of an older one) never says “up to date”: its line says “partly up to date: 28 in 2611, 385 in 2610” (and, if any, “n of unknown cycle”). Beside that button, **“Choose the file…”** opens the system chooser: the chosen file is sent to the workstation’s launcher (a progress bar, “Cancel”), which **recognises it by its content** (SIA, NATS, LFV, openAIP) and puts it where “Take the downloaded file” reads; the pickup (the plan, the question, the build of the zone) follows by itself. A file that is not recognised, empty, too large (1.5 GB at most) or of another type is refused, with the reason in words.

<a id="data-inventory"></a>**The data inventory.** Under the groups, a folded « Data inventory » block says what “data” covers on this workstation: seven lines (the data repository, the folder local to the workstation, the raw SIA sources, this device’s copy, the suite’s working folders, Downloads, the backups left behind), each with its size, “tracked”, “local” or “outside the repository”, and who writes it. It is read only when you open it. It reads no file, moves nothing, writes nothing; without a launcher, or with an old one, it says “inventory unreadable”. With a launcher that can do it, it also offers “Put the raw sources away”: the raw SIA XML files of data/sia/ go into data/local/sources/sia/<cycle>/. The plan comes first (the files and their size, never a path) and nothing moves before you confirm; each file is copied, checked, then the old one removed (kept if git tracks it, never deleted for every workstation). The result says which files were moved, already in place, kept and refused with their reason; “Put them back” undoes the move the same way. Nothing goes while another operation runs or a merge is pending, nor from a paired device.

<a id="data-journal"></a>**The journal.** At the foot of the screen, the last 50 operations of this device: UTC time, verb, zones, result.

## Special cases

- **Without a launcher**: the screen reads the same way; it shows what is published.
- **A read that fails**: the section says so in one line, the rest of the screen is drawn.
