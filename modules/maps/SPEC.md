# maps — specification (regeneration prompt)

This document describes the V3 map module completely enough for a developer or a language model to rebuild it without
seeing its code. Reference implementation: `modules/maps/module.js` (the screen), `modules/maps/render.js` (the
rendering core cut out of the V2 studio), `modules/maps/profile.js` (the vertical profile), `modules/maps/mission.js`
(a mission's maps), `modules/maps/lib/` (copies: ICAO symbols, the studio's profile code, MapLibre; generated: country
outlines, built-in display profiles).
Reading of the V2 studio: [READING.md](READING.md). How it is mounted and what it needs: [INTEGRATION.md](INTEGRATION.md).
Choices and measurements: [DECISIONS.md](DECISIONS.md).

## 1. Purpose

The Pilot application's map, read only, fast on a phone:
- the route map of the planned flight (lot 2) and its vertical profile with a common cursor (lot 3);
- the mission maps redrawn from what the mission stores (lot 4).

## 2. Inputs

- **The planned flight**: `pilot/<trigram>/current_flight.json` (written by fuel, schema in
  `modules/fuel/INTEGRATION.md`). Used: `route.points` [{ id, lat, lon, alt_ft? }], `route.dep`, `route.arr`,
  `route.altn`, `level.ft`, `aircraft.type`, `profile` { climbFpm, climbKt, descentFpm, descentKt, tocNm, todNm }.
  Nothing is written there.
  - `alt_ft` (fuel § 3): the level held from that point on, never on the first or the last point. The flight leaves
    at `level.ft`, and a point without `alt_ft` keeps the previous level. It becomes the point's `lvl` for the profile
    (like "/F240" in an OFP route): steps, TOC and TOD per segment; fuel's single-level `tocNm` / `todNm` are then not
    used. The map writes the level next to the point's name ("LMG · FL280").
- **The display setting**: `cache/maps/ui.json` { preset } (frame cache, per device).
- **Terrain**: Terrarium elevation tiles (AWS, zoom 9, about 300 m), read by the profile code itself (`meta.net`).
- **Aeronautical data**: `ctx.aerodb`, by area only.
- **Base map**: OpenFreeMap tiles (style `positron`) drawn by MapLibre; MapLibre calls the tile hosts itself (the
  hosts are listed in `meta.net`), never through `ctx.net`. Its own place names (symbol layers whose `source-layer` is
  `place`, or `place_labels` for Shortbread styles) are hidden while our towns are drawn (the Towns layer on and one
  `cities*` key in range, towns loaded), else shown again: no "Mérignac Mérignac", and a background without our towns
  (Topo, Towns off, out of range) keeps its names. Only the layers visible in the style are touched, on a change only;
  the list is read again at every `style.load` (a `setStyle` for the night or another profile).
- **Country outlines** (`lib/outlines.js`, generated by `tools/build_maps_outlines.py` from
  `shared/carto/aero_zones_geo.js`): the plain background when tiles are unavailable. Loaded at the first plain
  background (`meta.lazy`, the sea alone until they arrive, then redrawn); kept ahead (fetched once, so the service
  worker keeps them) only when MapLibre is not in the cache, so that a first flight offline still has its land.

## 3. Rendering core (`render.js`, `window.MapsRender`)

Everything is a parameter; nothing is read from a page or a data global. The projection is given:
`toC(lat, lon) → { x, y }` (MapLibre's `map.project`, or the Mercator projection of the plain background).

- `routeProfile(levelFt)` → the built-in "IFR route" display profile. It has the studio's profile shape (`zones`,
  `zoneList`, `zoneMode`, `corridorNm`, `elements`).
  - Airspaces: R, D, P, TRA, CTR, TMA, CTA, within 10 NM of the route.
  - Below FL195: low airways, and airspaces below 19,500 ft. From FL195: high airways, and airspaces above.
  - Aerodromes (public and state), VOR / TACAN / DME / NDB, MORA, graticule.
- `selectAirspaces(list, profile, route)` → the airspaces to draw:
  - kept by family, floor and ceiling (`SiaAero.limitFt`), and the white or black list;
  - then the corridor: a route sample inside the airspace, or an edge within `corridorNm`.
- `bboxOf(points, marginNm)`, `distances(points)` (great circle, NM), `marks(points, stepNm)` (every 10 NM, or every
  50 NM beyond 150 NM), `mercator(bbox, W, H, pad)` → `{ toC, shown }`.
- `drawBackground(ctx, toC, W, H, rings)`: sea, land, borders.
- `draw(ctx, { toC, W, H, scale, bbox, profile, data, route, marks })`. Drawing order:
  1. the route's labels are reserved first in the shared label placer (`SiaAero.placer`);
  2. airspace shapes (ICAO symbology, `SiaAero.drawAirspaces`);
  3. airways;
  4. aerodromes and navaids (`SiaAero.drawPoints`);
  5. airspace labels;
  6. graticule and MORA (the highest MORA of 2, 4… degree groups when a degree is narrower than 70 px);
  7. the route on top: line, points, NM marks and their labels.
- **Overview rule** (under 120 px per degree): only aerodromes and VOR / TACAN within 15 NM of the route, airways
  whose middle is within 30 NM, no obstacles. Closer views show everything the profile allows.
- **Density by zoom** (`tierOf(px per degree)`: far under 80, mid under 300, near beyond; `densify(data, tier,
  profile)`; mission maps are always drawn in full; with `vfrDensity`, VRP at every tier):
  - far: large aerodromes only, no navaids, airways with their boxed names;
  - mid: plus the airway points and the minimum level under each name ("F195");
  - near: everything, plus each segment's distance (NM) above the name, the true tracks near both ends ("097°"), VRP
    and obstacles.
- **Airways** (`drawAirways`), as en-route charts: low airways solid blue, high airways dashed purple; the name in a
  box laid along the segment (always readable left to right). The segment ends are drawn after them
  (`drawFixes`: a triangle and the id; a navaid at the same place is drawn with its own symbol instead). The boxes
  drawn are returned by `draw()` as `{ airways: [{ x, y, r, g }] }` for the tooltips.
- **AIP notation** (`sia(airspace)` → [main line, activation · information]; `siaLimit`): "TMA 8 AQUITAINE 2000|FL145
  D": SFC, FL### (FL999 → UNL), ASFC, plain feet AMSL. Airways: `awLimit(ft)` (FL from 5,000 ft, UNL from 66,000 ft).
  `airspacesAt(list, lat, lon)` and `airwaysAt(hits, x, y)` give what is under a point.

## 4. Screen (`module.js`)

- **Header**: title, "Edit the route" (opens `#fuel`), "Recentre", then the summary "dep → arr · alternate · level ·
  distance · type".
- **The map**:
  - 60 % of the screen height (at least 280 px), with the aeronautical layer on a canvas over MapLibre;
  - pan and pinch, no rotation, no pitch, Mercator, north up;
  - redrawn on every move (one frame at a time);
  - the alternate: a grey dashed line from the arrival, a grey dot and its code.
- **Data area**:
  - in overview (view at least 90 % as wide as the route's area), the route's area;
  - closer, the view widened by 15 %; read again only when the view leaves it;
  - airspaces and airways are read for the route's corridor only (`corridorNm` + 2 NM), leg by leg: one rectangle
    around a diagonal route would touch neighbouring zones (Spain for Nantes → Marseille).
- **Base map**: MapLibre is loaded at the first map (script and style sheet from `lib/`).
  - With no network, no WebGL, an error, or no style after 10 s, the map uses the plain background. It is fitted to
    the route and static.
  - The status line says "Base map unavailable: plain background".
- **Empty states**, written only when they change:
  - no flight: the map is hidden, with a message and "Open Fuel";
  - no published database: the route alone;
  - offline with no data for the area: a message and "Offline data" (`#settings`).
- **Updates**:
  - the flight file is watched (`ctx.data.watch`): a new `updated_at` refits the map and reads again;
  - `aerodb.on('change')`: the data are read again;
  - `ResizeObserver`: resize and redraw.
- **Map modes** (the user's validated mock-up, adapted to the `--sog-*` tokens; hidden for mission maps; icons only
  since lot 7a): a trigger at the top left showing the current mode's icon, the same size as the Layers button
  (`--sog-touch`), opens a row of six icon buttons; each has its name and help as tooltip and `aria-label`, the current
  one pressed (accent ring and inset shadow; red for CAM); the Layers button stays under the trigger.
  - Auto (wand, the flight's level: High IFR from FL195), Low IFR ("IFR" under a ceiling, `routeProfile(5000)`), High
    IFR ("IFR" over a floor, `routeProfile(30000)`), VFR (map icon, the built-in `vfr-detail` profile on the
    `ofm-liberty` base), Topo (contour lines drawn in CSS: `ofm-liberty` with a hillshade of the Terrarium tiles,
    aerodromes, towns and close-up obstacles only), CAM / OAT (red plane: the flight level's IFR plus refuelling and
    NAT tracks, R / D / P, TSA /
    TRA / CBA and the low-flying network at all levels, state aerodromes).
  - Icons from `frame/lib/icons.js` (`wand-sparkles` added, `map`, `plane`, `chevron-down`); colours: accent for the
    choice, `--sog-err` for CAM; corners from `--sog-radius` (square in cabinet and field).
  - Kept in `cache/maps/ui.json` (`preset`: auto, low, high, vfr, topo, cam); each mode has its own layers.
- **Tooltip** (lot 7a: one behaviour for hover, tap and click), a light `.mp-tip` (class `mp-hover`: `--sog-chart-bg`
  at 65 %, `--sog-fg`, thin border, 11.5 px, two lines at most) in the map box or the profile box:
  - what is under the pointer, in this order: a wind barb, an airway box, an airspace label (`draw()` returns their
    frames); on a tap or a click only, when no barb nor airway is under the
    finger (an airspace label does not count), the airspaces under the point in the levels card (`levelsHtml`, from one
    airspace on, its own element `.mp-lvcard`): the title "1 airspace at this point" or "n airspaces at this point", an SVG block like the vertical profile (altitude
    axis SFC to the highest finite ceiling with a nice step, "UNL" above, 66,000 ft and more counted as UNL; one
    numbered column per airspace from floor to ceiling, coloured by type as in the profile; ASFC limits counted from
    the ground), then the numbered list in SIA notation with activity and service, lowest floor first; the card stays
    inside the frame (scrolls if taller) and stays open: its ✕ (44 px) or Escape closes it, another tap on airspaces
    replaces it, a move of the map leaves it; the light tooltip stays for the mouse hover and for the targets that come
    first (barb, airway box, label);
  - a tap or click on one of the first three takes priority over placing the cursor on the route; on nothing, it
    closes the tooltip;
  - it follows the pointer 12 px away (never under it, kept in the box) while the pointer is on the label, stays 5 s at
    its last place (after the pointer leaves, or after a tap), gives way to the next one, and closes with a tap or click
    elsewhere or a move of the map;
  - the compatibility mouse events that follow a touch are ignored (`sourceCapabilities.firesTouchEvents`, or within
    1 s of a touch);
  - profile: the airspaces crossed at the cursor, two lines, same lifetime (5 s after the finger is lifted);
  - an airspace without limits in the base (FIR, UTA) shows no "SFC|SFC".
- **Camera**: once the user has moved or zoomed the map (any move that is not the module's own framing, `fitMap`),
  every redraw keeps the user's camera — a gesture of the Edit mode, the live view, fuel's requote. Only "Recentre"
  or another flight (departure or arrival changed) frames the route again; before any move of the user, a live update
  frames the route when it leaves the view.
- **Obstacles**: the studio's symbols (grouped on screen, the highest represents its group) without their label; in a
  close view (300 px per degree or more), "434 AGL (771)" beside the symbol — height above ground in feet, top
  elevation in brackets — where there is room.
- **Layers panel** (button with a layers icon under the presets; hidden for mission maps): airspace families (TMA /
  CTR: TMA, CTR, CTA, TMZ, RMZ; D / R / P: R, D, P, TRA, TSA, CBA, PJE, TRVL, TRPVL, ZIT; FIR: FIR, UIR, UTA, LTA, OCA,
  FRA; others: every other type present), lower and upper airways, beacons, airway points (`fixes`), VRP, obstacles,
  MORA, towns, graticule, alternate, and "Around the route only".
  - Defaults come from the preset's profile (a family is on when the profile names one of its types); the choices
    are kept per preset and per device in `cache/maps/ui.json` `{ preset, layers: { preset: { key: bool } } }`, only
    where they differ from the defaults; "Reset all" removes them.
  - The effective profile (`effectiveProfile()`) is the preset's with the layers applied: elements, `zones` (whole
    families), `otherZones`, `corridorNm`.
- **Around the route only**: on by default when the preset's profile has a corridor (IFR), off in VFR. Off, the data
  area follows the view (widened by 15 %) and airspaces and airways are read and drawn over all of it. In a close view
  (300 px per degree or more), everything in the view is read and drawn whatever the layer says.
- **VFR preset**: the studio's `vfr-detail` profile on the `ofm-liberty` base, plus beacons and `vfrDensity` (VRP at
  every zoom). Its families come from the layers: TMA / CTR and D / R / P whole (the studio's profile only names D, P,
  CTR and PJE, so a close view outside a CTR was bare).
- **Live view**: every write of the flight file redraws the map and the profile (debounced 300 ms,
  `performance.mark('maps:live')`); the view stays when the new route still fits in it; no zone is read again unless
  the data area changes.
- **Refuelling and NAT tracks** (`aarTracks`, `natTracks` elements; layers "Air refuelling tracks (AAR)" and "NAT
  tracks", on by default in CAM only; mission maps whose profile asks for them): read after the zones of the view
  (`aerodb.aarTracks()`, `aerodb.natTracks()`, which opens the `nat` zone); racetrack dashed in dark green with a light
  tint, outbound leg IP → CP as an arrow, the track's name beside it; heavy tracks as their two arrowed legs; NAT
  tracks dashed in slate through their points, "NAT A FL350–400" at the first point.
- **Winds aloft** (lot 6c; layer "Winds aloft", on by default; not on mission maps): from fuel's
  `route.points[].wind` (`{ dirDeg, kt, tempC, levelFt, at }`, the forecast at the level held at that point), a barb
  at each point that has one and every 50 NM between two such points, interpolated by components (and the temperature
  linearly). Classic barb: staff 30 px towards where the wind comes from, feathers on the low-pressure side (left
  with the wind at one's back in the northern hemisphere, right in the southern): pennant 50 kt, barb 10 kt, half barb
  5 kt, a circle under 3 kt; a 5 px background edge under it. Tooltip (mouse hover, or a tap, which takes priority
  over the cursor on the route): "Wind 290° / 65 kt", then temperature, level (`formatLevel`) and forecast hour.
- **Profile marks**: the route's points, and the airway points and navaids within 3 NM of the route (at least 30 px
  apart), as small triangles with their id.
- **TOC and TOD on the map**: their label goes north-east of the diamond, else south-east, north-west, south-west,
  wherever it does not cover a route label (`draw()` returns their frames).
- **"Edit the route"** opens `#fuel?from=maps&focus=route` (fuel's Route step, text field focused).
- **Editing the route on the map** (lot 6a; hidden for mission maps): an "Edit" toggle at the top right of the map
  box, with "Undo" beside it in the mode; the line under the profile gives the gestures.
  - A press within 22 px of a waypoint (not departure nor arrival) drags it: the press is caught before MapLibre
    (`pointerdown` in the capture phase, `mousedown` / `touchstart` / `touchmove` stopped while dragging), so the map
    does not pan; anywhere else the map pans as usual.
  - While dragging: rubber band from the previous to the next point, the anchor under the finger (navaid, aerodrome,
    airway point, RNAV point, VRP of the data read, within 20 px) ringed with its id. Released on it: the point takes
    its id and position, and keeps its `alt_ft`. Released elsewhere: a free point at the finger's position, named by its ICAO
    coordinates (`icaoCoord`, "4530N00030E"), for VFR and helicopters; an anchor within 20 px keeps the priority.
  - Adding is an explicit gesture: the "+" button of the bar (shown in the mode, pressed while armed) arms one
    insertion, and the next tap adds the anchor under the finger (else a free point at its ICAO coordinates) where it
    lengthens the route least, then disarms; a press held 500 ms without moving (8 px) does the same at once (the
    browser menu is suppressed in the mode). A simple tap never inserts: on a route point it opens its card, elsewhere
    the map's tooltip. A tap on a route point opens its
    card (id, departure / arrival or the level held from it, "Remove" for a waypoint); the click that follows a drag
    is ignored.
  - Levels (lot 6b): in the mode, a vertical drag on the profile (more than 6 px) sets the level held on the segment
    under the finger, in steps of 1,000 ft, shown as a dashed line with its level while dragging; a tap without
    dragging places the cursor as usual. The level applies from the point that opens the segment: on the first
    segment it is `level.ft`, elsewhere the point's `alt_ft`, removed when it equals the previous segment's level. In
    the mode the profile has `touch-action: none` (the page does not scroll under the finger). A point's card shows
    the level held from it with "−" and "+" (FL10).
  - "Undo" restores the points and the flight level before the last gesture (20 kept, in memory).
  - Each gesture is shown at once (points, header, profile); 400 ms after the last one, the record is written:
    `route.points` (rounded to 1e-6°), `route.text` from fuel's `textFromPoints(points, previousText,
    previousPoints)` (`frame/lib/route_text.js`: the airway between two neighbouring points left unchanged is kept,
    the one of a changed segment drops; ICAO coordinates for a point without a usable name), `level.ft` when the first
    segment's level changed, `distanceNm`, `trackDeg`, `from: 'points'`, `manual: false`, `by: 'maps'`, `updated_at`,
    merged into the latest version read (no other field lost).
  - The live view takes a version of the record only if it is newer than the one shown: the write of an earlier
    gesture, coming back after newer gestures, would otherwise undo them.
  - While the record is not `by: 'fuel'`, the profile ignores fuel's `profile` (TOC, TOD) and computes its own;
    fuel redoes the quote and writes it back (`modules/fuel/INTEGRATION.md` § 3).
- **Levels** are written as everywhere in the suite, by `formatLevel(ft)` of `frame/lib/route_text.js` ("FL060" from
  the transition altitude, "3 500 ft" below): header, route labels (given to `draw()` as `level`), the point card,
  the level being dragged, the planned altitude under the profile. Heights (relief, MORA) stay in feet.
- **Texts**: four languages, through `ctx.t`. Data labels (codes, names, levels) are not translated.

## 3 bis. Beacons in the same place

- `SiaAero.drawPoints` (copy of the studio, diverging here) takes places from the highest rank to the lowest: TACAN, VOR,
  DME, NDB, ILS / LOC (a DME paired with an ILS comes after its ILS: it is the same installation, the ILS symbol
  carries "(D)"); an ILS's place includes its feather. A beacon without place is attached to the nearest kept one;
  close up (300 px per degree and more) every beacon is drawn except one whose symbol would fall on a kept one
  (VOR BZH and ILS BG at Brest, 0.04 NM; ILS and DME CLI at Calvi, same point). Drawing goes from the lowest rank to
  the highest, so an ILS stays underneath.
- `drawPoints` returns `{ navaids: [{ n, x, y, merged }] }`; `render.draw()` returns them as `navaids`. Over a beacon
  (within 9 px), the tooltip gives "VOR BZH 110.65" and either "also here: ILS 25L BG 109.9" (the attached ones) or
  its name.

## 4 bis. Vertical profile (`profile.js`, `window.MapsProfile`)

- **Cut**: `SiaProfile.build` (copy of the studio's code). 100 to 800 samples along the route; terrain is the highest
  point on the line and 1 km either side; airspaces crossed are the sample intervals inside their rings.
- **Airspaces**: those of the route profile's types along the route (2 NM boxes, leg by leg), without the floor and
  ceiling filter. Only those that the planned trajectory enters are kept. Limits relative to the ground (ASFC) are
  raised by the terrain. Without a trajectory (no level), all are kept.
- **Trajectory**:
  - with fuel's `profile` and a level: linear climb from the departure's terrain to the level over `tocNm`, cruise,
    linear descent to the arrival's terrain over `todNm` (fuel's own climb and descent);
  - otherwise `SiaProfile`'s own plan, with fuel's rates if given, else 1,000 ft/min at 140 kt up and 800 ft/min at
    160 kt down.
  TOC and TOD are the ends of the cruise.
- **Terrain unavailable** (offline, or the first tile refused): the cut has no terrain. The MORA of each 1° cell
  crossed is drawn as a dashed brown step line (aerodb `mora`), and the status line says so.
- **Drawing**: `SiaProfile.draw` (axes in ft / FL, airspace bands and labels, terrain, points with their distances,
  trajectory with TOC / TOD and the cruise level), scale 0.78 under 500 px. Labels use the copy's `strictLabels`
  option: the airspaces the trajectory enters first (then the widest), each label only against its own band (inside,
  just above or just below), never over another label, TOC / TOD or the bottom 18 px (NM marks); a label without room is
  not drawn and the count goes to "+n" in a reserved box at the top right of the cut. Then:
  - the NM marks of the map, as small ticks at the bottom of the frame;
  - the airway points and beacons within 3 NM of the route, a small triangle and the id, skipped where an airspace
    label already sits (`geo.taken`);
  - the cursor, on its own canvas: a vertical line and a dot at the planned altitude.
- **Common cursor**:
  - a finger or the mouse on the profile sets the distance;
  - a tap on the map within 32 px of the route sets it to the nearest sample;
  - the map shows it as a blue ring, with TOC and TOD as purple diamonds.
- **The strip under the profile**: distance (NM) · planned altitude · terrain or MORA · the airspaces under the cursor
  (type, name, limits), or "outside the airspaces shown". Without a cursor, a one-line hint.
- **API**: `build(points, { levelFt, profile, airspaces, elevation, mora })`, `draw(ctx, cut, { W, H, scale })` →
  geometry, `xOf(geo, s)`, `sOf(geo, x)`, `at(cut, s)`, `posAt(cut, s)`, `nearest(cut, toC, x, y, maxPx)`; distances in
  metres, altitudes in feet.

## 4 ter. Mission maps (`mission.js`, `window.MapsMission`)

- **Address**: `#maps?mission=<ID>&map=<file>`. Without `map`, the mission's first map; without `mission`, the planned
  flight.
- **Choosers**: in the header, "Planned flight" then every mission of the repository; for a mission with two maps or
  more, a second chooser with its maps (description, else file name). Choosing changes the address; the frame mounts
  the module again.
- **Missions**: `missions/<l>_<FAMILY>/<ID>/mission<ID>.yaml`.
  - The list comes from the data layer's tree (`list('missions/')`); nothing is read to list them.
  - Only the chosen mission's YAML is read (policy "reference"), and parsed with `frame/lib/js-yaml.min.js`.
  - A change to that file (`watch`) reads it again.
- **Parsing** (the studio's rules, `parseMissionYaml`):
  - points: origin, destination, target, alternate, turning points, rendezvous;
  - zones: circle or polygon; kind search, exclusion or mission;
  - `maps[]`: file, type, description, centre (`centre_ref` or `center`), `bbox` / `range_km` / `width_km` /
    `height_km`, `view`, `profile`, `trace`; maps with profile `off` are left out;
  - `vertical_profile`: route, cruise, rates.
- **Fields written by the V2 studio** (BUGS SOG, develop ea077ae36, v3 f799f8429):
  - `profile_def`: the full display profile, used as is;
  - `resolved_bbox`: the extent drawn;
  - `cycle`: the AIRAC cycle of the map. A cycle different from aerodb's is said in the status line.
  - In `vertical_profile`: `profile_def`, `cycle`, `route_points` [{ name, lat, lon, alt_ft }].
- **Without those fields** (older missions):
  - **Profile**: the built-in profile of the same id, else the built-in profile of the type. Detail, target and rdv
    give `vfr-detail`; approach gives `vfr-simple`; anything else gives `ifr-simple`. The status line says so.
  - **Extent**: `view`, else `bbox`, else the automatic frame by type:
    - general: points and zones, 12 % margin;
    - zone: the zone, 20 % margin;
    - detail: 8 × 5 km; target: 100 × 62 km; others: 220 × 140 km;
    - widened to the studio's 1.6 ratio.
  - **Route**: `vertical_profile.route` (or origin, turning points or target, destination), parsed by
    `SiaProfile.parseRoute`. Names resolve against the mission's points and zones, then aerodb's `coords`. The levels
    of the text (FL240 then FL260) are kept.
- **Drawing**: the map's profile decides everything: base style (OpenFreeMap and VersaTiles styles; the studio's own
  style, OSM and OpenTopoMap become `positron`), airspaces, airways, aerodromes, navaids, obstacles, VRP and RNAV
  points, cities, MORA, graticule. Then:
  - the mission's zones (hatched, dashed outline, name);
  - the mission's points (dot and name, labels reserved first);
  - the route when `trace` is `route` or `both`, or by default when the mission draws its route on maps.
  No overview declutter: a mission map shows what its profile asks for.
- **Vertical profile**: the mission's route with its levels and rates. Airspaces come from the `vprof` profile (copy,
  else built-in: every type). The common cursor works as for the flight.
- **Not drawn** (later, if asked): probable route and exercise tracks, operation maps, AAR tracks, NAT, built-up
  areas, summits, relief and contour layers.

## 4 quater. Designs, day and night (frame/design)

- **Page**: frame primitives only (`f-tools`, `f-btn`, `f-muted`); the module's own style only places things.
  Backgrounds use `--sog-bg` (map box) and `--sog-chart-bg` (profile); the credit line uses `--sog-chart-bg` and
  `--sog-fg`.
- **Canvas**: `MapsRender.tokens()` reads `--sog-chart-bg`, `--sog-bg`, `--sog-fg`, `--sog-muted`,
  `--sog-chart-grid` and `--sog-accent` with `getComputedStyle(document.documentElement)`. Night is a chart background
  darker than 45 % luminance.
  - `MapsRender.themed(ctx, tokens)` wraps the 2D context. Paper colours written by value, in this module and in the
    studio's copies, are replaced as they are set:
    - white (backgrounds, halos, label boxes, any alpha) → `--sog-chart-bg`;
    - ink → `--sog-fg`; greys → `--sog-muted`; rules → `--sog-chart-grid`;
    - at night, a dark cartographic colour is lightened by 45 % toward white, alpha kept.
    Other cartographic colours pass unchanged.
  - The cursor (ring on the map, line and dot on the profile) is `--sog-accent`.
  - The plain background is sea `--sog-bg`, land `--sog-chart-bg`, borders `--sog-chart-grid`.
- **Base map at night**: OpenFreeMap `dark` (VersaTiles profiles: `eclipse`).
- **Changes**: a change of `data-design` or `data-tone` on `<html>`, or of `prefers-color-scheme`, reads the tokens
  again. The module switches the base style when night changes, then redraws the map and the profile.

## 4 septies. VFR reporting points of an aerodrome (VAC)

- **Data**: the reporting points of the published base first, always (`aerodb.vrp({ lat, lon, radiusNm: 30 })`: those
  whose id carries the aerodrome's prefix, "MN-" for LFMN; otherwise those within 15 NM; code shown as the VAC writes
  it, "HE" for MN-H-HE), then the VAC compilation when imported (`aerodb.vfrRoutes(icao)`, aerodb SPEC § 5 quater,
  `sia/vfr/<ICAO>.json`): its sequences, instructions, manual vertices and the reporting points the base does not
  have. Both read once per aerodrome and kept for the session.
- **One point, one drawing**: a VAC point is the base's VRP it was matched with at import (`vrp`), else the nearest
  base VRP of the aerodrome within 0.6 NM (a compilation imported before the helicopter points were matched, a code
  written otherwise); it is drawn once, at the base's position with the base's name, the VAC code in its tooltip when it
  differs ("VAC code: HE"), its restrictions too. Only unmatched VAC points and manual vertices are added. While an
  aerodrome is shown, `render.draw({ hideVrp })` leaves its VRPs out of the VRP layer (no second symbol or label).
- **Colours of the VFR reporting points**, everywhere (VRP layer, highlighted points, labels, the card): fixed wing in
  the text colour (`--sog-fg`), rotary wing in green (`#2e7d32`): "-H-" in the base's id (MN-H-HE), confirmed in the
  published base (`MapsRender.vrpRotary`, `vrpColor`). Sequences and tracks from the VAC stay teal.
- **Which aerodromes**: `render.draw()` returns the aerodromes it drew with their screen position (`aerodromes:
  [{ a, x, y }]`); an aerodrome is under the pointer within 12 px.
- **Hover** (mouse; an airway box, a barb or an airspace label pass first): preview of the aerodrome's points and
  sequences; tooltip "LFMN NICE COTE D'AZUR · 21 reporting points · 5 VAC sequences: tap to see them", or "… · VAC
  sequences: not imported" without the compilation. Leaving the aerodrome or the map ends the preview.
- **Tap or click** (not in Edit mode, not on a mission map): the aerodrome is pinned. When its points span less than
  160 px on screen, the map fits them (aerodrome included, zoom 11 at most, room left for the card); that is the
  user's gesture, so the camera stays theirs afterwards (Follow stops, Recentre comes back). Then its card:
  - "LFMN NICE COTE D'AZUR: VFR reporting points", then "Reporting points (n)" with the legend "(black: aeroplanes;
    green: helicopters)" when both kinds are there, one line per point (coloured code, name, restrictions read in the
    VAC); without the compilation, "VAC sequences: not imported" and nothing else;
  - with it, the warning "Extracted from the VAC charts, to be checked: this is not
    the published route, the VAC chart prevails", the counts;
  - the sequences in text ("LFBD – NA – NE (page 6)"), identical ones (same codes, same page) shown once, with "(some
    may be only part of a route)" when any is marked `fragment`;
  - the instructions of the VAC, one folded block per page (its title, its page).
  The card goes to the side opposite the aerodrome, under the buttons of that side; under 600 px it takes the lower 45 %
  of the frame and the fit leaves that room. The card has its own element (`.mp-adcard`) and stays open while the map
  moves or is tapped elsewhere: its ✕ (44 px, top right) or Escape closes it and releases the aerodrome; another
  aerodrome replaces it. The points and sequences stay highlighted while it is open.
- **Tap targets** (22 px, a finger): first a reporting point (the highlighted ones, whose aerodrome is known, then
  those of the VRP layer, `render.draw()` returning them as `vrps`: the aerodrome of their prefix within 30 NM, else
  the nearest within 5 NM) when it is nearer than an aerodrome: its aerodrome is pinned, the point first and in bold in
  the list; a VRP without aerodrome gives its own tooltip (code, name). Then an aerodrome. Both before the tooltips and
  the levels card.
- **VFR mode**: departure and arrival (four-letter codes) are shown anyway, drawing only.
- **Drawing**, on top of the route (teal): a route with an interpreted geometry follows it (long dashes, its manual
  vertices as small dots), the others are short dashes between their known reporting points; never a line to the
  aerodrome's centre (an integration not digitised stays undrawn, format 2's rule); an arrow at the end of a route
  only when an analysis made it one-way (`direction: 'forward'`). Each reporting point ringed and named (code, then the
  base's VRP name when loaded); the aerodrome's reference point is not drawn; "VAC, to be checked" in italics under
  the aerodrome.
- **Format 2 in the card**: the analysis line ("Manual analysis of the VAC (partial)", "Automatic extraction, not
  reviewed", "Analysis out of date (the VAC changed): automatic extraction only", "VAC reviewed: no published
  sequence") and its notes; each route with its name (`key`), codes and pages, then runways, default altitude, minimum
  visibility and "one way" when read, and the omission note (what is not digitised). Counts are of reporting points.
  Then the number of track vertices placed by hand ("…, accuracy not guaranteed", or "within n m" when every vertex
  has an `accuracyM`) and the points with a restricted use, each with its restrictions as written in the VAC; such a
  point is drawn with a dashed ring.
  A first-format file (`page` per route, no analysis) is read the same way.

## 4 sexies. Started flight (lot 8)

While the current flight carries `started` (not null; fuel sets it back to null when the start is cancelled, Report
when the report is saved), nothing otherwise:
- **Planned position** (`progress.plannedPos { lat, lon, legIndex, nmFromDep }`, written by fuel every minute):
  hollow aircraft in the accent colour, turned to the route's track at that point, labelled "planned 14:32Z"
  (`progress.at`); its along-route distance is `nmFromDep`, its altitude the profile's at that distance. While fuel says
  the aircraft taxis (`progress.phase: 'taxi'`, about 10 minutes), the planned aircraft stays at the departure
  aerodrome, on the ground (distance 0, the profile's altitude there); the climb starts at the planned take-off (phase
  `climb`).
- **Actual position** (`progress.actual`, written by the frame from the GPS or the network; one older than
  `started.at` is the previous flight's and is ignored, trail included): filled red aircraft turned
  to `trackDeg` (else the bearing from the previous position); the trail of the last 30 minutes dotted (kept in memory
  from the successive positions, plus `actual.trail` when given). Older than 2 minutes: greyed, "Position from n min
  ago". The line ends with the source (`actual.source`: `gps`, `network`, `ivao`, `vatsim`, `xplane` "X-Plane", `lnm`
  "Little Navmap"); any other value: no label, no error.
- **Difference**, a line above the map: ahead or late in minutes and NM (both positions projected on the route; time at
  `actual.gsKt`, else 250 kt), cross-track distance and side, actual altitude against the planned one at that
  distance (`formatLevel`). Without an actual position: "GPS or network not enabled" with a link to `#settings`.
- **Profile**: filled dot at the actual distance and altitude, circle at the planned position.
- **ETA** (`progress.eta`, a list `[{ id, at }]` in the order of the points; a table `{ id: at }` is read too): "ETA 14:52Z" for
  each point in a close view (300 px per degree and more), a route label in the accent colour: `withEta` adds `eta` to
  the points given to `render.draw()`, and `routeLabels` reserves it in the placer with the other route labels, before
  the aerodromes (under the point's name, else above the point, else on its left, the first free place); departure and arrival add the device's local time,
  "ETA 16:10Z (18:10)". Every time of the map (ETA, "planned 14:32Z", wind forecasts) comes from `frame/lib/time.js`
  (`fmtZ`, `fmtZLocal`).
- **"Follow"** (in the bar at the top right, shown only during a started flight): keeps the map centred on the actual
  position at each update (a move of the module, marked as such); any move of the user stops it (camera rule).
- **Updates**: a write of the record that changes only the progress (same points, level and start) redraws the map and
  the profile without reading the zones nor building the profile again.

## 4 quinquies. Zoom thresholds, contour lines, tuning of the profiles (lot 7b)

- **Zoom thresholds**: every element drawn on a flight map has a range of MapLibre zoom (512 px tiles; `zoomOf(px per
  degree)`, `pxOfZoom(z)`) in which it is shown, per mode: `profile.elements.zoom = { key: [min, max] }` (max 24: no
  upper limit; a key without a range is always shown). Keys (`ZOOM_KEYS`): airspace families `asFir` (FIR, UIR, UTA,
  LTA, OCA, FRA), `asTma`, `asCta`, `asCtr`, `asR`, `asD`, `asP`, `asTsa` (TSA, TRA, CBA), `asOther`; `zoneLabels`
  (airspace names); `awLow`, `awHigh`, `awLabels` (segment distance and tracks); `navaids`, `fixes` (airway points),
  `vrp`, `obstacles`, `mora`; `citiesBig` (200,000 and more), `citiesMid` (30,000), `citiesSmall`; `graticule`, `aar`,
  `nat`, `wind`, `contours`.
  - `atZoom(profile, z)` cuts the elements out of their range; `byZoom(data, profile, z, tier)` keeps the data shown
    (families, beacons, VRP, obstacles, MORA, towns); from afar (`tier` far) only the large aerodromes. Mission maps are
    not concerned (their studio profile shows what it asks).
  - The view's zoom is shifted by ¾ of a level per step of the "Complexity (trial)" slider of the Layers panel (−2 to
    +2, per mode and device), so the whole set moves together; a map frame narrower than 600 px (pane of the dual
    view, phone) takes one step less.
  - Starting values (`ZOOM_IFR`, `ZOOM_VFR`): in IFR (Auto, Low, High IFR, CAM) the route corridor already thins the
    map, so the airspaces are graded in one intermediate step: the overview shows the route, the winds, the
    aerodromes and the shapes of TMA, CTA, R and TSA / TRA (the only ones above FL195); CTR, D and airspace names from
    4.75, airways from 5, P from 5.25, other airspaces and MORA from 5.5; beacons and airway points from 5.75, segment labels from 7.75, VRP from
    9.25, obstacles from 8.5, medium towns from 6.5, small towns from 8.5, contours from 9); in VFR and Topo the
    airspaces are graded: FIR up to 7, TMA and CTA from 6, R, D and TSA from 6.5, CTR from 7, P from 7.5, others from 8,
    names from 6. Landmarks: France on a screen ≈ 5.5, on a phone ≈ 4.3, 100 NM wide on a screen ≈ 8.5.
  - Precedence: the built-in values, then the airline's (`airline/map_profiles.json`), then the device's
    (`cache/maps/ui.json`, `layers[mode].zoom`), then the values being tuned (`#maps?tune=1`).
- **Contour lines** (`contours.js`, `window.MapsContours`): computed in the browser from the Terrarium tiles (the
  host of the relief, nothing new): marching squares on each tile's elevation grid (a cell every 2 tile pixels),
  segments kept per tile and interval, projected at each drawing; tile zoom from the view (8 to 12, at most 16 tiles);
  in memory only (48 tiles). Interval 500 ft (or 100 m when the pilot's altitude unit is metres, `fuel.json`
  `displayAlt`), every fifth an index contour, thicker and numbered. Drawn under the aeronautical overlay, in VFR and
  Topo, within the `contours` range (from 9) and with the "Contour lines" layer.
- **Tuning of the profiles (administrator)**: `#maps?tune=1`, reachable by its address only (no button, nothing in the
  user help). A panel beside the live map (on a screen of 1,000 px and more; above the map otherwise; read only on a
  phone): the current zoom (and its NM per cm of screen), the six mode tabs, one line per key with a double slider
  "from … to …" (zoom 0 to 18, step ¼; 18 means no upper limit) labelled in zoom and NM per cm, the current zoom
  marked on each slider. The map is redrawn at every move of a slider. In front of each line, a "drawn" box: the
  Layers panel's layer for that line in this mode (`LAYER_OF`: one box per airspace family — TMA / CTA / CTR share
  "TMA / CTR", R / D / P / TSA share "D / R / P" —, the three town sizes share "Towns"; airspace and airway names are
  two new layers, `zoneLabels` and `awLabels`, in the panel too). Unticked: never drawn whatever the range; the sliders
  stay adjustable, greyed. Ticking here or in the panel is the same choice, kept at once on the device
  (`cache/maps/ui.json`, `layers[mode]`). "Reset the boxes" (the mode's built-in layers for those lines), "Reset the
  sliders" (the mode's starting values),
  "Keep on this device" (`cache/maps/ui.json`), "Save for the airline" (`airline/map_profiles.json`: the
  thresholds in `profiles[mode].elements.zoom`, the boxes in `profiles[mode].layers`, read as the mode's starting
  layers before the device's choices).
- **Map size**: the MapLibre canvas follows the frame. A size observer on the frame, the map's `load` and
  `style.load`, the page's return (`visibilitychange`, `pageshow`, `resume`: observations made while the tab was hidden
  or frozen are lost) and every redraw compare the canvas with its container and call `map.resize()` only when they
  differ; the observer also reaches a map still loading its tiles.
- **The airline's profiles** — `airline/map_profiles.json`, record (merge `record`, the newest `updated_at` wins):

```json
{
  "schema": 1,
  "updated_at": "2026-10-23T18:00:00Z",
  "by": "maps",
  "profiles": {
    "vfr": {
      "base": "ofm-liberty",
      "zones": ["D", "P", "CTR", "PJE", "FIR"],
      "elements": {
        "vrpPoints": true,
        "zoom": { "vrp": [9.25, 24], "asCtr": [7, 24], "asTma": [6, 24], "asFir": [0, 7] }
      }
    },
    "auto": {}, "low": {}, "high": {}, "topo": {}, "cam": {}
  }
}
```

  - `profiles[mode]` is a display profile in the studio's `profile_def` format (`base`, `layers`, `cities`,
    `population`, `zones`, `zoneList`, `zoneMode`, `corridorNm`, `elements`), complete or partial: what it carries
    replaces the built-in profile's fields, and its `elements` (and `elements.zoom`, key by key) are merged into the
    built-in ones. Modes: `auto`, `low`, `high`, `vfr`, `topo`, `cam`.
  - V3 extensions of `profile_def`: `elements.zoom` (above), `elements.vfrDensity`, `hillshade` (Topo relief),
    `elements.fixes`, `elements.awLabels`.
  - The device's override stays in `cache/maps/ui.json` (`layers[mode]`: the Layers panel's ticks, `detail`, `zoom`).
  - Changes of the file are followed (`ctx.data.watch`): the map takes them at once.

## 5. Invariants

1. Read only: the module writes nothing (`meta.writes` is empty).
2. A module file is never read from outside `modules/maps/` or the frame (the service worker keeps only those); V2
   files are copied into `lib/`, unchanged, with their origin in a header line.
3. No interface text in `render.js`.
4. The plain background always works offline once seen, or when MapLibre is not cached (core and symbols are in
   `meta.files`; the outlines are in `meta.lazy`, kept ahead in that case).
